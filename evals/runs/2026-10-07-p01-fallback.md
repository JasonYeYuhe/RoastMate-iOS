## Run C — a retired primary (`--var DEFAULT_MODEL:qwen/qwen3-retired-test-does-not-exist`)

**Native `models` alone does NOT cover this.** OpenRouter validates every id
before routing: with `models: [nonexistent, qwen3-next]` both probes returned
**502 ← openrouter:400** in 3.5 s. OpenRouter's docs list rate limits,
downtime, moderation and context length as fallback triggers — an unknown id
is a request error, not a routing failure. A retired model is exactly that
case, which is the failure P0.1 exists for.

Fix: the Worker retries with the tail of the list on any failure
(`routing.js` `openRouterAttempts`: `[a, b]` → `[[a, b], [b]]`, one call per
model at most). Re-run after the fix:

| locale | status | latency | model |
|---|---|---|---|
| `zh_TW` | 200 | 4.7 s | `qwen/qwen3-next-80b-a3b-instruct` |
| `en_US` | 200 | 3.9 s | `qwen/qwen3-next-80b-a3b-instruct` |

Worker log: `OpenRouter attempt failed: openrouter:400` once per request, then
served. Total well inside the app's 25 s `CloudConfig.requestTimeout`.
