Reviewer notes — RoastMate v1.4.0

1. WHERE GENERATION RUNS.
Calm / Sharp / Savage and the "Make it sendable" rewrite run ON-DEVICE via
Apple's Foundation Models where available; the rewrite is on-device only.

Vent and Feral are different and we want to be explicit: Apple's on-device
model refuses to produce genuine vent output, so these two modes send the
typed situation to our own Cloudflare Worker, which forwards it to a
third-party LLM provider (currently Groq, OpenRouter as fallback). This
happens ONLY after a separate, explicit in-app consent (Guideline
5.1.2(i)) shown before any text leaves the device, revocable anytime in
Settings > AI & Privacy. Our proxy is stateless; we do not retain text.
The "roommate group" feature in the Echoes tab is cloud-only for the same
reason, behind the same consent.

NOTE: earlier versions of this document wrongly said the app was
on-device only. Corrected here.

2. POSITIONING.
A creative-writing / emotional-expression tool, not a harassment tool.
No field for a target person's name — only a SITUATION. Safe Mode on by
default. Vent and Feral produce PRIVATE drafts labelled "for yourself
only", not presented as messages to send. A user-initiated "Rewrite as
Sendable" runs a second on-device pass that strips profanity (no slurs,
threats, sexual content, or doxxing).

TEST PATH: Roast Generator > Intensity "Vent" > type any situation >
Generate. The card is labelled "Vent draft - for yourself only" with a
do-not-send banner. Tap "Make it sendable" for the sendable version.

3. WHAT'S NEW IN 1.4.0.
- VOICE INPUT FIX. The app never configured its AVAudioSession, so the
  microphone captured nothing — the sheet opened, no text appeared.
  Fixed for both the iOS 18 (SFSpeechRecognizer) and iOS 26
  (SpeechAnalyzer) paths. Transcription stays 100% on-device
  (requiresOnDeviceRecognition = true); a locale with no on-device model
  hides voice rather than using any network path.
- Pro subscribers using the roommate group are now counted against the
  Pro allowance rather than the free one.
- Share card hardening. The card renders only the sendable reply and its
  text is immutable — no free-text field reaches the renderer, so nothing
  a user types can appear on a RoastMate-branded image. Before drawing,
  the text is scrubbed on-device for names, phone numbers, ID numbers and
  WeChat/QQ contacts, then re-validated by the safety filter; if that
  refuses, no card is produced.
- Private drafts remain unshareable (1.3.1): no share sheet, no
  share-as-image, no text selection. Copy is kept as an explicit
  user-initiated action.
- Some capabilities ship DISABLED behind remote flags, not reachable in
  this build.

4. iCLOUD SYNC IS ACTIVE (earlier versions of this document said
"planned"; corrected here). History, threads, saved situations, settings
and credit-ledger entries mirror via SwiftData + CloudKit into the PRIVATE
database of the Apple Account on the device (container
iCloud.yyh.roastmate.app). That is the user's own iCloud storage: it never
reaches our servers and we cannot read it.

5. ACCOUNTS. Sign in with Apple is OPTIONAL and gates no feature; only the
Apple user ID and any shared name are stored locally in Keychain. No
content shared between users, no social features, no analytics SDK, no
advertising IDs, no third-party SDKs.

6. PURCHASES (unchanged from 1.3.1).

- yyh.roastmate.app.pro.yearly ($19.99/yr, 7-day trial)

Pro is verified server-side: the app sends the StoreKit 2 transaction JWS
to our Worker, which validates Apple's signature and issues a short-lived
token granting the higher cloud quota. The JWS carries no name, email or
payment detail.

7. Share Extension and App Intents expose only Calm / Sharp — neither can
produce a private vent draft. 17+; first launch shows an age confirmation.
